# Запуск и приёмка на olenenka_dwh_test

## Подготовка

Подключите PostgreSQL 18 к базе olenenka_dwh_test с шестью загруженными таблицами приватного исторического RAW. Комплект содержит побайтовые копии принятых SQL. Проверить их можно по SHA256SUMS в корне.

## Пересборка

RAW должен содержать текущий приватный снимок. Файлы 01_raw не включены в пересборку. Они предназначены для разового развёртывания пустой базы. COPY использует путь, доступный серверу PostgreSQL, и требует прав чтения. Скрипты первоначальной загрузки RAW используют локальные пути к исходным CSV. Перед использованием в другой среде эти пути необходимо адаптировать. Исторические RAW-данные в репозиторий не включены.

~~~powershell
& 'C:\Program Files\PostgreSQL\18\bin\psql.exe' `
  -X -W -P pager=off -v ON_ERROR_STOP=1 `
  -v target_db=olenenka_dwh_test `
  -h 127.0.0.1 -p 5432 -U postgres `
  -d olenenka_dwh_test `
  -f '.\sql\00_rebuild.sql'
~~~

Полный сценарий запускается через psql. Отдельные модули подходят для VS Code после создания зависимостей. Сценарий требует явного указания target_db и проверяет его совпадение с фактической базой подключения. Дополнительно запрещена пересборка исходной базы olenenka_dwh. Для предотвращения одновременных запусков используется advisory lock. Все модули выполняются в одной транзакции REPEATABLE READ, внутренних COMMIT в подключённых файлах нет. При ошибке psql завершает сеанс и незавершённая транзакция откатывается. В ручном сеансе после ошибки выполните ROLLBACK.

## Повторная проверка

21.11.2026 владелица проекта дважды подряд выполнила полную пересборку в локальной PostgreSQL 18 на базе olenenka_dwh_test с приватным RAW. Оба запуска завершились COMMIT, кодом 0 и прохождением Data Quality. Контрольные показатели финансовой сверки, ABC и XYZ совпали.

1. Запустите сценарий и сохраните локальный лог вне Git. Проверьте код возврата 0 и финальный COMMIT.
2. Выполните 02_data_quality/06_historical_snapshot.sql. Проверьте контрольные числа и 13 исключений по ID и отклонению.
3. Повторите полный запуск. Ожидаются тот же COMMIT и те же показатели. Это проверяет пересоздание VIEW, таблиц и индексов.
4. Выполните отдельно 03_mart_integrity.sql и 05_bi_reconciliation.sql. Они должны завершиться без исключений.
5. Проверьте сводки ABC/XYZ в конце файла снимка.
6. Перед публикацией изучите git status --short и git diff --cached --name-only. В списке не должно быть exports, CSV/XLSX, дампов, архивов, логов или temp.sql. .gitignore не удаляет уже отслеживаемые файлы и их историю. Первый публичный репозиторий создавайте из чистого комплекта. Если история уже содержит приватные файлы, сначала нужна отдельная очистка.

## Проверка отката при необходимости

После двух успешных прогонов можно проверить откат отдельным тестом без редактирования проекта. В одной psql-транзакции выполнить модуль sales_monthly.sql, затем SELECT 1/0. При ON_ERROR_STOP подключение завершается без COMMIT. После повторного подключения сравнить таблицу с прежним состоянием. Только на olenenka_dwh_test. Этот тест в рамках аудита не выполнялся.
